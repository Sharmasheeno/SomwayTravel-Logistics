# Macruf Travel and Cargo Agency

Full-stack website and agency operations system for Macruf Travel and Cargo Agency.

The project includes a public marketing website, cargo and visa tracking, a protected owner workspace, staff accounts and role-based permissions, client records, cargo, tickets, visas, expenses, daily reconciliation, receipts, status PDFs, reports, and optional customer email updates.

## Technology

- Frontend: React 19, TypeScript 5.9, Tailwind CSS 4, served by Vinext and Vite 8
- Backend: Node.js, Express 5, MongoDB (Mongoose) — all authentication and application data (users, tickets, cargo, visas, expenses, suppliers, clients, daily closes, rates, starting balances, activity log)

The frontend and backend are two separate processes: Vite serves the UI on `http://localhost:5173`, and Express serves the API on `http://localhost:5000`. The frontend talks to the API over HTTP with a session cookie.

## Requirements

- Node.js 22.13 or newer
- npm 11 or newer
- MongoDB running locally (or a `MONGODB_URI` connection string to a remote instance)
- Linux, macOS, or Windows with WSL

The included build helpers use Bash, `flock`, and GNU `timeout`. On macOS, install GNU coreutils or run the project with a Linux/WSL environment.

## Local setup

1. Extract the ZIP and open a terminal in the extracted folder.
2. Install the exact locked dependencies:

   ```bash
   npm ci
   ```

3. Make sure MongoDB is running locally (or set `MONGODB_URI` in your environment / `.env.local` to point at a remote instance).
4. Start the API:

   ```bash
   npm run server
   ```

5. Seed the default users (safe to re-run — it updates existing accounts instead of duplicating them):

   ```bash
   npm run seed:users
   ```

6. In a separate terminal, start the frontend:

   ```bash
   npm run dev
   ```

7. Open `http://localhost:5173`. The public website is at `/`. The private owner setup and login page is at `/admin`.

Seeding the first users:

`npm run seed:users` creates one owner, a second owner and a Nairobi
operator. It takes their addresses and passwords from the environment and
generates a strong random password for anything you do not supply, printing
the result once when it finishes. Copy those passwords out of that output --
they are not stored anywhere and cannot be recovered afterwards.

```bash
SEED_OWNER_EMAIL=you@example.com SEED_OWNER_PASSWORD=... npm run seed:users
```

Never commit a real password to this file or to the seed script. Running the
seed also **resets** the password of any account it matches by address, so do
not run it against production.

The frontend's API base URL defaults to `http://localhost:5000`; override it with `VITE_API_BASE_URL` if the API runs elsewhere.

## Optional customer email delivery

PDF status downloads work without an email provider. To send status emails, copy the example environment file and add a valid Resend API key and a sender on a verified domain:

```bash
cp .env.example .env.local
```

Then edit `.env.local`:

```dotenv
RESEND_API_KEY=your_resend_api_key
MACRUF_FROM_EMAIL="Macruf Travel and Cargo <updates@your-verified-domain.com>"
```

Do not commit or share `.env.local`.

## Main routes

- `/` — public agency website and cargo/visa tracking
- `/admin` — owner setup and login
- `/portal/[token]` — dedicated staff login links generated by the owner

## API overview (`server/`)

All application data lives in MongoDB behind the Express API, with one Mongoose collection per entity (`server/models/`): `User`, `Session`, `Ticket`, `Cargo`, `Visa`, `Expense`, `Supplier`, `Client`, `DailyClose`, `Rate`, `StartingBalance`, `Activity`, `AgencySettings`.

- `POST /api/auth/setup-owner`, `GET /api/auth/status`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`, `GET /api/auth/link` — authentication, session-cookie based.
- `GET /api/admin/users`, `POST /api/admin/users`, `PATCH /api/admin/users`, `PATCH /api/admin/account` — owner-only staff management.
- `GET /api/data`, `PUT /api/data` — read/write the full role-scoped snapshot of tickets, cargo, visas, expenses, suppliers, clients, daily closes, rates, starting balances, and the activity log. Role rules (office scoping, cost hidden from officers, consultants read-only) are enforced server-side in `server/lib/agencyData.js`.
- `POST /api/notifications/status` — emails a cargo/visa status update via Resend.
- `GET /api/public/track` — unauthenticated cargo/visa tracking lookup.

## Security and deployment notes

- Passwords are hashed with bcrypt; raw passwords are never stored.
- Sessions are opaque tokens hashed with SHA-256 before being stored in MongoDB, delivered to the browser as an HTTP-only cookie.
- Financial information and owner controls are restricted by role, enforced on the API.
- Do not include `.env.local`, `.wrangler`, `.sites-runtime`, `node_modules`, or production database files when sharing source code.
- Before using the system in production, configure a managed MongoDB instance (e.g. Atlas), HTTPS, backups, a verified email sender, and appropriate network/access controls.
